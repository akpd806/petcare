# Спецификация требований к проекту

## 1 Введение

### 1.1 Назначение
Документ определяет полные требования к веб-приложению "PetCare" - клиентскому инструменту учёта здоровья и рациона домашнего питомца: расчёт нормы кормления, журнал кормлений, учёт вакцинации с напоминаниями, визуализация динамики веса.

### 1.2 Область применения
Приложение предназначено для частных владельцев кошек и собак. Коммерческое применение, ветеринарные клиники и породные питомники на этапе MVP не охватываются.

### 1.3 Определения и сокращения
- **MVP** - минимально жизнеспособный продукт;
- **Операционный прототип** - первая рабочая сборка для проверки гипотез;
- **LocalStorage** - хранилище Web Storage API браузера (~5 МБ на домен).

## 2 Общее описание

### 2.1 Перспектива продукта
PetCare - автономное клиентское веб-приложение. Серверная часть, база данных и внешние API на этапе MVP отсутствуют: вся персистентность обеспечивается LocalStorage. Приложение не интегрируется с ФГИС «ВетИС» и сторонними сервисами.

### 2.2 Характеристики пользователей
Основной пользователь - владелец 1-3 питомцев без технической подготовки. Особый сегмент - пользователи 45+ с низкой цифровой грамотностью: интерфейс не должен требовать обучения.

### 2.3 Ограничения
1. Индивидуальная разработка (один разработчик), срок - до 15.05.2027.
2. Нулевой бюджет: только бесплатные инструменты и библиотеки (MIT-лицензии).
3. Ёмкость LocalStorage ~5 МБ - ограничивает объём фото и истории записей.
4. Браузерные push-уведомления доступны только при открытом сайте - напоминания реализуются как внутрисайтовые баннеры + Notification API.

### 2.4 Предположения и зависимости
Пользователь работает в современном браузере с включённым JavaScript и Web Storage; данные не синхронизируются между устройствами.

## 3 Пользовательские требования (сценарии)
| ID | Сценарий | Основной поток | Результат |
|----|----------|----------------|-----------|
| UC-1 | Зарегистрировать питомца | Пользователь вводит кличку, вид, породу, дату рождения, пол, вес | Профиль сохранён, рассчитана возрастная группа |
| UC-2 | Узнать норму кормления | Пользователь открывает раздел "Кормление" | Показаны граммы/сутки и кратность приёмов |
| UC-3 | Отметить кормление | Пользователь нажимает "Покормлен" у ближайшего приёма | Запись в журнале, баннер напоминания скрыт |
| UC-4 | Внести прививку | Пользователь выбирает вакцину и дату введения | Рассчитана дата следующей ревакцинации |
| UC-5 | Получить напоминание | Система сверяет даты при открытии приложения | Показано напоминание (кормление / прививка за 7 дней) |
| UC-6 | Зафиксировать вес | Пользователь вводит дату и массу | Точка добавлена в историю |
| UC-7 | Посмотреть динамику | Пользователь открывает раздел "Вес" | Линейный график за выбранный период |

## 4 Функциональные требования
Приоритеты по MoSCoW: **М** - обязательно в MVP, **S** - следует сделать, **C** - можно сделать, **W** - не будет (границы проекта).

- **FR-1 (М) Профиль питомца:** создание, редактирование, удаление; поля: кличка, вид, порода, дата рождения, пол, текущий вес, ссылка на фото; до 3 профилей на устройство;
- **FR-2 (М) Расчёт нормы кормления:** по справочнику «порода * возрастная группа» (грамм/сутки, кратность); при отсутствии породы в справочнике - по формуле RER = 70 * (вес, кг)^0,75 с коэффициентом активности;
- **FR-3 (М) Журнал кормлений:** отметка приёма с датой/временем и объёмом; сводка "съедено сегодня / норма";
- **FR-4 (М) Учёт вакцинации:** справочник вакцин с интервалом ревакцинации; дата следующей = дата введения + интервал; отметка "сделана";
- **FR-5 (М) Напоминания:** при открытии приложения - баннер о пропущенном кормлении и о прививке за 7 дней до срока; опционально Notification API;
- **FR-6 (М) Учёт веса и график:** добавление замеров; линейный график за 3 / 6 / 12 месяцев; отображение дельты за период;
- **FR-7 (S) Экспорт / импорт данных:** выгрузка и восстановление всех записей в формате JSON;
- **FR-8 (C) Несколько питомцев:** переключение профилей в шапке;
- **FR-9 (W) Регистрация, онлайн-оплата, чат, интеграция с ветклиниками:** не реализуются.

## 5 Нефункциональные требования

### 5.1 Пользовательский интерфейс
1. Адаптивная вёрстка: контрольные точки 360 px (мобильный), 768 px (планшет), 1280 px (десктоп).
2. Минимальный размер кликабельной области - 44×44 px.
3. Контрастность текста не ниже 4,5:1 (WCAG 2.1 AA).
4. Язык интерфейса - русский; все формы с валидацией и подсказками.
5. Навигация - не более 2 кликов до любой функции с главной.

### 5.2 Производительность
1. Загрузка главной страницы <= 1 с на десктопе и <= 4 с в мобильной сети 3G.
2. Оценка Lighthouse: Performance >= 90, Accessibility >= 90, Best Practices >= 90, SEO >= 90.
3. Размер стартового JS-бандла <= 200 КБ (включая Chart.js).
4. Отрисовка графика из 100 точек <= 300 мс.

### 5.3 Надёжность
1. Сохранение данных между сессиями: после перезагрузки страницы все записи восстанавливаются.
2. Валидация ввода: вес 0,01–150,00 кг с шагом 0,01; дата не позже текущей.
3. Корректная обработка переполнения LocalStorage (сообщение пользователю, а не падение).

### 5.4 Безопасность и приватность
1. Персональные данные не передаются по сети: весь трафик - статические файлы.
2. Экранирование пользовательского ввода (защита от XSS).
3. Отсутствие сторонней аналитики, трекеров и рекламных SDK.

### 5.5 Сопровождаемость и переносимость
1. Кроссбраузерность: Chrome 120+, Firefox 120+, Safari 17+, Edge 120+.
2. ОС: Windows 10+, macOS 12+, Android 10+, iOS 15+.
3. Размер собранного дистрибутива (`build/`) <= 5 МБ.
4. Модули кода сопровождаются JSDoc-комментариями; структура папок - по разделу "Структура проекта" README.

## 6 Требования к интерфейсу (структура сайта)
1. **Главная (дашборд):** карточка питомца, ближайшее кормление, ближайшая прививка, дельта веса за месяц.
2. **Профиль:** форма данных питомца с фото и кнопкой сохранения.
3. **Кормление:** суточная норма, список времён приёмов, журнал за сегодня.
4. **Прививки:** список вакцин с датами "последняя / следующая", добавление записи.
5. **Вес:** график, выбор периода, форма добавления замера.
6. **Шапка:** логотип, навигация по 5 разделам.
7. **Футер:** версия сборки, ссылка на репозиторий.
8. **Страница 404** для несуществующих маршрутов.

## 7 Технические требования
1. Стек: Astro 4+, JavaScript/TypeScript, Chart.js 4+, пакетный менеджер Bun 1.4.x.
2. Хранение: Web Storage API (LocalStorage), схема данных JSON v1 (соответствует ER-модели, рисунок 2 отчёта).
3. Внешние API на этапе MVP не используются.
4. Репозиторий: GitHub; ветка `main` - стабильные сборки; теги `v0.1` (прототип), `v1.0` (релиз).

## 8 Требования к первой работающей сборке (прототипу)
Прототип (тег `v0.1`) обязан уметь:
1. создавать и редактировать один профиль питомца;
2. рассчитывать и показывать норму кормления;
3. отмечать кормления с сохранением в LocalStorage;
4. отображать 3 страницы (главная, профиль, кормление) в адаптивной вёрстке.
Не обязан: напоминания, прививки, график, экспорт.

## 10 Порядок контроля и приёмки
1. Функциональное тестирование по тест-плану (`docs/TEST_PLAN.md`): 100% требований приоритета М покрыты тест-кейсами.
2. Юзабилити-тестирование: не менее 5 респондентов из ЦА; успешность типовых задач >= 80 %; средняя оценка удобства >= 4 из 5.
3. Приёмка научным руководителем: демонстрация релизной сборки + защита отчёта.
